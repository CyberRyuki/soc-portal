# Integración con Microsoft 365

Sección **Microsoft 365** del portal: alertas de Defender XDR, inicios de sesión y usuarios en riesgo (Entra ID),
reglas de correo sospechosas, auditoría del directorio, Secure Score y estado del servicio. Las acciones sobre cuentas
se confirman siempre por una persona (motivo obligatorio, auditoría y nota en el incidente).

## 1. Registrar la aplicación en Entra ID

1. **Entra ID → Registros de aplicaciones → Nuevo registro** → «Portal SOC ACME», *solo esta organización*.
2. Copia el **Id. de directorio (inquilino)** y el **Id. de aplicación (cliente)**.
3. **Certificados y secretos → Nuevo secreto de cliente** (caducidad 12–24 meses). Copia el valor (solo se ve una vez).
4. **Permisos de API → Agregar → Microsoft Graph → Permisos de aplicación**:

| Para | Permisos (aplicación) |
|---|---|
| Alertas de Defender | `SecurityAlert.Read.All` |
| Inicios de sesión y auditoría | `AuditLog.Read.All`, `Directory.Read.All` |
| Usuarios en riesgo | `IdentityRiskyUser.Read.All`, `IdentityRiskEvent.Read.All` |
| Secure Score | `SecurityEvents.Read.All` |
| Estado del servicio | `ServiceHealth.Read.All` |
| Reglas de bandeja de entrada | `MailboxSettings.Read`, `User.Read.All` |
| **Acciones** (opcional) | `User.RevokeSessions.All`, `User.EnableDisableAccount.All`, `User-PasswordProfile.ReadWrite.All`, `IdentityRiskyUser.ReadWrite.All`, `SecurityAlert.ReadWrite.All`, `MailboxSettings.ReadWrite` |

5. **Conceder consentimiento de administrador para ACME.**

> Microsoft no deja que una aplicación bloquee o cambie la contraseña de **administradores** con más privilegios que ella:
> esas acciones fallan con 403 y se hacen desde el centro de administración.

## 2. Configurar el portal (`.env`)

```bash
M365_TENANT_ID=<id del directorio>
M365_CLIENT_ID=<id de la aplicación>
M365_CLIENT_SECRET=<secreto>
M365_READ_ONLY=false          # true: solo ver, sin acciones
M365_FOUR_EYES=false          # true: la contención la aprueba otra persona
M365_POLL_MIN=5               # cada cuántos minutos se leen las alertas de Defender
M365_SUGGEST_SEVERITY=high    # proponer incidente con alertas de esta severidad o más (vacío = no proponer)
M365_HOME_COUNTRY=DO          # inicios de sesión desde otro país se marcan para revisar
M365_RULES_SCAN_USERS=300     # buzones que revisa «Revisar buzones» (primero los usuarios en riesgo o con alertas)
```

El servidor necesita salida HTTPS a `login.microsoftonline.com` y `graph.microsoft.com`.

## 3. Qué hace cada pestaña

- **Alertas**: Defender for Office 365 / Endpoint / Identity / Cloud Apps, con evidencias (usuarios, IP, URL) cruzadas con el
  motor de IoC. Las de severidad ≥ `M365_SUGGEST_SEVERITY` aparecen como **sugerencia** en Incidentes.
- **Inicios de sesión**: fallidos, con riesgo y **correctos desde el extranjero** (posible cuenta robada). Por usuario, IP y país.
- **Usuarios en riesgo**: Entra ID Protection (requiere P2 / E5) y detecciones de los últimos 7 días.
- **Correo**: reglas que reenvían a dominios fuera de los verificados del tenant o que borran/ocultan mensajes.
- **Auditoría**: cambios de roles, acceso condicional, consentimientos de aplicaciones, credenciales y contraseñas.
- **Secure Score**: puntuación, comparación con otras organizaciones, recomendaciones que más suman y estado de servicios.
- **Acciones**: revocar sesiones, bloquear/desbloquear, forzar cambio de contraseña, confirmar compromiso / descartar
  riesgo, resolver alertas y desactivar reglas. Desde Shuffle (`POST /portal/api/m365/actions` con `X-API-Key`) quedan
  pendientes hasta que una persona las aprueba.
